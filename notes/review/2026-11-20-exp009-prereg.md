# Review of the exp009 pre-registration (2026-11-20, before results)

On EXPLOG "## exp009" (6367599), the switch (92d8f21), and tools/shiftc_tab.py (9320814, 98044c8). The arms, the
identity checks and the measure do what the entry says. Two of the four points below are errors in my own 405e315
prediction, which the entry quotes. They should be corrected by amendment before any run finishes.

## 1. C relaxes in every population, so "near 0 in CTLRAND" is wrong (major; my error, and the steward's prediction shares it)
C is read by nothing, in the herd or in the wild. Its pull toward 0.5 therefore acts in CTLRAND's herd and in every
arm's wild goats exactly as in CTLDEEP's herd. Drift adds variance but does not change the expected mean; each allele's
expected path is the mutation process alone, and C is unlinked (free recombination, C18). Expected: C's fraction is the
same in CTLDEEP, CTLRAND and REF, and the same in the herd and the wild. The prediction "near 0 in CTLRAND" (mine) and
"in CTLRAND within 0.10 of 0" (the steward's) contradict the very hypothesis being tested. Under it, they are expected to
fail.

The contrast that carries the test is trait against C *within* an arm:
- CTLDEEP: do A, H and T move about as far toward 0.5 as C does?
- CTLRAND: A, H and T track the wild, which selection holds (exp007: herd change within 0.025 of wild change), while C
  still relaxes. So CTLRAND's trait fractions should sit near the wild's, and well below C's.

**Fix (amendment):** replace both CTLRAND predictions with "C's fraction in CTLRAND equals CTLDEEP's within noise; A,
H and T's fractions in CTLRAND are below C's". Read a C fraction that differs between arms beyond noise as a sign that
something other than mutation moves C, which would invalidate C as the pull's reference.

## 2. The width bar will probably fail on CTLDEEP's herd C alone; pool the pull estimate (major)
In exp007 CTLDEEP's herd change for C had SE 0.044 at 8 seeds (split_founders.txt), so a per-seed SD of about 0.12. As a
fraction of (0.5 − F_C), the per-seed SD is 0.12 / (0.5 − F_C). C started at U[0.6, 1] at year 0 (mean 0.8) and relaxes
for 400 years before the founders' window, so F_C may sit near 0.70-0.75. My arithmetic for the 95% half-width at 16
seeds (t 2.131) is then:
- denominator 0.20: about 0.32;
- denominator 0.25: about 0.26;
- denominator 0.30: about 0.21.

All of these are over the 0.20 bar, so the registered reading is likely "unresolved" by design.

**Fix:** under the hypothesis the pull is the same everywhere (point 1), so the registered estimate of the pull should
pool C's fraction over every population in the batch:
- herd C in CTLDEEP and CTLRAND (32 runs);
- wild C in the same runs, as a second, partly independent estimate;
- REF's herd and wild C if wanted.

Report CTLDEEP-only C as a secondary. Apply the width bar to the pooled estimate. Then check that the arms agree
(point 1) before pooling, since that agreement is part of the test.

## 3. The comparison is not symmetric; add readings for traits below and above C (minor)
By year 400, C's alleles have spread from a uniform start for about 130 generations. A, H and T have sat at
mutation-selection balance, narrower: founder genotype SD 0.105-0.107 for A and H and 0.078 for T, against C's 0.137 in
exp007's unshifted run. A wider distribution puts more alleles within a step of the bound, so C's pull per unit distance
is probably faster than a held trait's. The registered readings cover "traits inside C's interval" and "C below 0.15,
traits near 0.4-0.5". Add two:
- **Traits clearly below C:** the pull is present and the traits' direction is the pull's, partly opposed by selection
  in the herd's environment.
- **Traits clearly above C:** selection in the herd pushes the same way as the pull, beyond it.

## 4. REF has no prediction and no role in the decision rule (minor)
The entry gives REF as context. State what it is compared with. REF's own A and H fractions in exp007 were 0.26 and
0.10 (split_founders.txt), with the spook filter and keep value on. A REF trait fraction well below the pooled C
fraction would mean REF's selection holds that trait against the pull.

## On the amendment (a2f5c04), before any result
It answers points 1-4. Three small things remain:
- **Pooling within runs:** average each run's herd C and wild C fractions first, then take the interval over runs (32
  values). That handles the within-run correlation without a model.
- **The validity check is a non-significance test.** "Within 2 SE" passes more easily the noisier C is. Report the
  CTLRAND − CTLDEEP difference with its 95% interval beside the pass/fail, so a reader can see how much disagreement
  the check could have missed.
- **The per-trait readings ignore the trait's own uncertainty.** "Inside the pooled C's interval" compares a trait's
  point estimate with C's interval. Read each trait from the paired within-run difference fraction(C) − fraction(trait)
  and its interval, which the scorer already prints: an interval spanning 0 means inside, entirely above 0 means
  below C, and entirely below 0 means above C.
